# Organize Notes

整理 `D:\notes` 中的 Markdown 笔记。本 skill 的数据根目录固定为 `D:\notes`；触发时不得读取或写入当前项目目录中的笔记、`format.md` 或 `ignore.md`。

## Source of truth

每次触发时，先读取 `D:\notes\format.md`，并把它作为唯一的排版规范来源。不要把规范复制到本 skill，也不要读取当前项目中的同名文件或依赖之前读过的版本；如果 `D:\notes\format.md` 被用户修改，立即以最新内容为准。

同时读取 `D:\notes\ignore.md`：

- `ignore.md` 中列出的笔记文件名表示已经完成排版整理。
- 这些笔记跳过格式整理，但仍然可以被引用。
- 它们也可以补充指向新笔记的引用。
- 文件名按笔记的项目相对路径记录，以避免不同目录出现同名笔记时产生歧义，例如 `knowledge/沙箱.md`、`idea/研究主题.md`。

如果 `D:\notes\ignore.md` 不存在，在 `D:\notes` 下创建它，并使用简短说明和一个空的 Markdown 列表。不要把 `format.md`、`ignore.md` 或本 skill 文件加入笔记清单。

## Scope

扫描 `D:\notes` 中所有目录下的 Markdown 笔记，而不是只扫描 `knowledge/`：

- 包括 `knowledge/`、`idea/` 以及以后创建的其他笔记仓库或目录。
- 排除 `.git/`、`.claude/`、`.agents/`、`.obsidian/`、构建输出目录、依赖目录和隐藏的工具目录，除非用户明确要求整理其中的文件。
- 通过相对于 `D:\notes` 的路径识别文件；不要因为目录名称变化而限制扫描范围。
- 只有扩展名为 `.md` 的文件才是候选笔记。

将候选笔记分为两类：

1. **未整理笔记**：不在 `D:\notes\ignore.md` 中的笔记。触发时必须按 `D:\notes\format.md` 调整排版。
2. **已整理笔记**：在 `D:\notes\ignore.md` 中的笔记。触发时跳过排版，但要作为引用目标参与关系分析。

“未整理笔记”特指不在 `D:\notes\ignore.md` 中的笔记，不以文件修改时间或 Git 状态判断。用户要求新建的笔记，无论是否已经写入 `D:\notes\ignore.md`，都必须先按“新建笔记”规则创建，再按本 skill 的检查清单验证。

## 新建笔记

当用户要求创建一篇新笔记时，必须把 `D:\notes\format.md` 作为创建阶段的格式规范，并将文件写入 `D:\notes` 下合适的目录，而不是只在创建后整理：

1. 先扫描现有笔记，确认是否已有同主题或近似主题的笔记；能复用或补充已有笔记时，不重复新建。
2. 根据主题选择 `D:\notes` 下合适的现有目录，并使用简洁、明确且与主题一致的文件名；不要擅自改变已有目录结构。
3. 创建文件时从 `# 主题名称` 开始，文件开头不得有空行；标题层级从 `#` 连续开始，正文段落、列表、表格和代码块之间按 `D:\notes\format.md` 保留空行。
4. 新笔记至少包含一到两句开头定义，并按内容需要组织核心概念、工作方式或示例；内容足够完整时使用 `## 总结`，不为套模板虚构内容。
5. 代码、命令、路径、文件名和配置键按 `D:\notes\format.md` 使用反引号；独立代码块必须使用正确语言标识，无法判断时使用 `text`，且围栏必须成对。
6. 创建正文时只写用户提供或已核实的事实，不补充未经核实的外部信息、凭据或个人信息；术语、列表、表格、强调和标点遵循 `D:\notes\format.md`。
7. 创建前确认相关已有笔记的实际路径；在正文首次自然提及处添加至少一条有帮助的 Wiki 链接，无法自然嵌入时在文末添加 `## 相关笔记`。避免重复、自引用、歧义或失效链接。
8. 写入后按“Validate and report”检查标题层级、空行、代码围栏和新增链接目标。只有格式检查成功后，才将新文件相对于 `D:\notes` 的路径加入 `D:\notes\ignore.md`；失败或需要用户决定时不得加入。

## Workflow

### 1. Inventory

1. 读取 `D:\notes\format.md` 和 `D:\notes\ignore.md`。
2. 扫描所有符合范围的 `.md` 文件。
3. 解析 `D:\notes\ignore.md` 中相对于 `D:\notes` 的路径，并检查每个条目是否仍然存在。
4. 对不存在的旧条目不要静默删除；在最终报告中提示，并保留原条目，除非用户明确要求清理。
5. 区分未整理笔记和已整理笔记，先建立候选笔记标题、主题和已有链接的索引。

### 2. Format unorganized notes

对每个未整理笔记：

- 按最新 `D:\notes\format.md` 修复标题层级、空行、段落、列表、表格、代码围栏、强调格式和明显的格式残留。
- 仅在确有需要时补充标题、开头定义或 `## 总结`；不要为了套模板强行扩写。
- 修复明显的错别字、聊天残留、游离语言标签和残缺 Markdown，但不改变原文事实、技术含义、观点或语气重点。
- 不随意重命名文件，不改变目录结构，不删除有意义的内容。
- 代码块保持可复制运行；不能确定语言时使用 `text`。
- 不添加未经核实的外部事实、链接、凭据或个人信息。
- 修改前先读取文件，完成后检查代码围栏是否成对、标题层级是否连续、文件是否有开头空行。

### 3. Add helpful references

对所有笔记（包括已整理笔记和本次整理的未整理笔记）建立引用关系：

- 只添加真正有帮助、主题相关且目标文件确实存在的 Obsidian Wiki 链接，例如 `[[笔记名]]`。
- 优先在正文首次自然提及相关主题的位置加入链接；无法自然嵌入时，在文末添加 `## 相关笔记`。
- 新笔记至少添加一条指向已有相关笔记的引用（如果确实存在相关笔记）。
- 允许已整理笔记新增指向新笔记的引用；不要因为它在 `ignore.md` 中而禁止这类修改。
- 允许新笔记之间互相引用，但避免无意义的全量互链。
- 对同名文件使用带路径或别名的 Wiki 链接，避免产生歧义；先确认目标存在。
- 不重复添加已有链接，不添加指向自身的链接，不创建失效链接。
- 处理链接时保留已有链接和用户原有组织方式，除非它们明显失效或违反 `D:\notes\format.md`。

### 4. Update ignore.md

只有在某个未整理笔记的格式整理完成并完成检查后，才把它相对于 `D:\notes` 的路径加入 `D:\notes\ignore.md`。每行一个 Markdown 列表项，使用稳定的相对路径，例如：

```markdown
- knowledge/CI验证.md
- idea/研究主题.md
```

已整理笔记即使只新增了引用，也不需要重复记录。不要把格式整理失败、无法读取或需要用户决定的文件加入 `ignore.md`。

### 5. Validate and report

完成后检查：

- `D:\notes\format.md` 和 `D:\notes\ignore.md` 未被误当作笔记整理。
- 所有未整理且成功完成的笔记都已加入 `D:\notes\ignore.md`。
- `D:\notes\ignore.md` 中的已整理笔记没有被意外改写格式。
- 所有新增 Wiki 链接的目标文件存在。
- 没有重复、自引用或明显无帮助的新增链接。
- 修改后的代码围栏成对，标题层级符合 `D:\notes\format.md`。

最终报告列出：

- 整理格式的笔记路径。
- 新增引用关系（来源 → 目标）。
- 仅新增引用、未改格式的已整理笔记。
- 跳过或失败的文件及原因。
- `D:\notes\ignore.md` 新增的条目。

## Safety

- 所有笔记、引用和 `ignore.md` 的创建或修改都必须写入 `D:\notes`；不写入当前项目目录。
- 不提交 Git，不推送，不删除笔记，不重命名文件，不覆盖用户未要求处理的非 Markdown 文件。
- 不修改 `D:\notes\format.md`；它只能由用户手动维护。
- 不擅自清理 `D:\notes\ignore.md` 中已不存在的条目。
- 如果格式规范与原文含义发生冲突，优先保留原文含义，并在报告中说明。
